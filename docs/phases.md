# Roadmap

## Phase 0 — Foundation ✅ (this delivery)
Restructure into feature modules, add the missing global error handler, centralize env validation (Zod), structured logging (Winston), Docker + docker-compose, ESLint/Prettier/Husky, and a Jest + Supertest + mongodb-memory-server test harness with CI. Pure infrastructure — no business-logic bug fixes, no new features.

## Phase 1 — Auth & user domain rebuild ✅ (this delivery)
Fixed the business-logic bugs identified in the original code review that live in the auth/user/hof/verification path (field-name mismatches, the `ref: "HOF"` casing bug, the `addMembers` temporal-dead-zone bug, the broken manual validation). Collapsed the three JWT middlewares into one role-aware `verifyAuth`. Replaced manual field checks with Zod schemas via `validate.middleware.js`. Added refresh-token rotation with reuse-detection, shared between the user and HOF modules. Added rate limiting on login/register/OTP endpoints. Full test coverage for auth, refresh rotation, and OTP verification flows.

## Phase 2 — Family domain completion ✅ (this delivery)
Fixed the remaining field-name mismatches scoped to the family module (`isActive`/`is_active` in `removeMember`, `member.relationship`/`relationship_to_hof` in the list/detail endpoints). Fixed the ownership/authorization gap on the verification-revoke endpoints — split into `revoke-member` (must be in the calling HOF's own family) and `revoke-hof` (self only). Added Zod validation to all family routes. Added pagination to `get-all-members`. Removed the manual try/catch-into-500 pattern in favor of the global error handler. Full test coverage for family creation, membership, pagination, and the revoke-authorization fix.

## Phase 3 — Verification & notifications hardening ✅ (this delivery)
Moved email sending off the request/response cycle onto a BullMQ/Redis queue — `registerUser`/`sendVerificationOTP` now enqueue a job and return immediately instead of blocking on a live SMTP round-trip, with retries if SMTP is temporarily down. Extracted the OTP email into a real HTML template file instead of an inline literal, with the expiry duration read from one shared constant instead of two copies that could drift. Added a dedicated worker process (`src/worker.js`) deployable independently from the web server. Found and fixed two related production-hardening gaps along the way: ioredis crashing on an unhandled connection error, and nodemailer hanging indefinitely with no connection timeout.

## Phase 4 — Observability, security & scalability ✅ (this delivery)
Replaced `express-mongo-sanitize` (verified broken on Express 5 — crashes on any request with a query string) with a custom sanitizer for `req.body`/`req.params`; kept `hpp` only for what it actually still does under Express 5 (body parameter pollution, not query). Added request-ID correlation (`X-Request-Id`) through logs and error responses. Added Redis-backed caching for the family module's expensive populate/format operations, with version-counter invalidation on writes. Generated `docs/openapi.json` directly from the app's Zod validation schemas instead of hand-maintaining YAML, with a CI check that fails the build if the spec drifts from the code. Also made Redis (queue + cache) fully optional — `REDIS_URL` unset means zero Redis connection attempts and a synchronous fallback, not just a graceful failure.

## Phase 5 — Media & E2E messaging ✅ (this delivery, with an important scope correction)
Built the server-side half of an E2E-encrypted messaging system: a public-key directory (identity key, signed prekey, one-time prekeys — shared between User and Hof) and an opaque ciphertext relay (Message model), scoped to same-family messaging. Added Socket.IO for real-time delivery, JWT-authenticated at the handshake. **Explicitly did not** implement the Signal Protocol's actual cryptographic operations (X3DH, Double Ratchet, encrypt/decrypt) on the backend — those belong client-side for the system to genuinely be end-to-end encrypted; doing them server-side would defeat the point. See `docs/messaging.md` for the full explanation and what's still needed (signed-prekey signature verification, delivery receipts, group messaging — all flagged as explicit follow-ups, not silently skipped). **Media/file attachments were not built this pass** — the original scope for this phase included extending the Cloudinary flow to encrypted message attachments; text messaging was already substantial enough to warrant its own careful pass, so attachments are pushed to a follow-up rather than rushed alongside it.

## Phase 6 — Deployment & CI/CD
Environment-specific configs, automated deploy pipeline, Sentry + basic metrics.
